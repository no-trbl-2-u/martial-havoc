## Outcome

Two things, both in `packages/content`, plus the engine that reads them:

1. **The format** — `packages/content/schema/adventure-format.md`, a
   versioned document (`v1`), plus the record shapes it describes added
   to the one JSON Schema.
2. **The cave** — `packages/content/data/campaigns/the-5-treasures/`,
   the whole of The 5 Treasures written in that format: premise, event
   table, eight areas, per-area encounter tables, loot rows, five
   treasures, locks and keys, flags, act markers, an ending screen, and
   an original SVG room diagram.
3. **The engine** — `packages/engine/src/adventure/`, pure functions
   over an immutable `AdventureState` with the dice injected, every
   export labelled.

**Done when** (the build-plan row): the format's document and the cave's
file are in the content package; **a scripted Master reaches the ending
screen on fixed dice** — that last clause is a Vitest test, not a screen.

## Why a format and not just a file

`spec.md` refuses an authoring tool but makes the format public. So the
cave must be *data in a documented shape*, not code with the cave inlined.
The test of the format is that a second adventure could be written in it
without touching `packages/engine`. Every decision below is made in that
direction: nothing about the Lotus Flower cave is hard-coded in the engine.

## The format, v1

An adventure is a **directory** under `data/campaigns/<adventure-id>/`,
holding one content file per record kind. Every file is the existing
envelope (`id, kind, title, cite, label, docs, records`) — standing rule
"one schema" holds; this phase adds record shapes, never a second schema.

| File | Record kind | Holds |
|---|---|---|
| `adventure.json` | `adventureMeta` | id, title, version, premise (verbatim), first area, credits |
| `events.json` | `band` (existing) | the 1d6 event table: Ambush / Encounter / Safe exploration / Hint |
| `areas.json` | `adventureArea` | the eight areas |
| `encounters.json` | `adventureEncounter` | per-area encounter tables |
| `loot.json` | `adventureLoot` | the LOOT line of each foe, as rows |
| `treasures.json` | `adventureTreasure` | the five treasures |
| `flags.json` | `adventureFlag` | day/night, the nap, the sheets, the spells |
| `acts.json` | `adventureAct` | act markers and the ending screen |
| `map.svg` | (not a record file) | the original room diagram |

Foes stay where they are: `data/campaigns/the-5-treasures-foes.json`
already holds the nine blocks in the `opponent` shape, and the build-plan
row says "the foes file stays". `areas.json` and `loot.json` reference
those ids; a content test asserts every reference resolves.

### `adventureMeta`
```
id            adventure.<slug>
version       "1" — the format version this file is written in
title         the adventure's printed title
premise       the premise paragraph, verbatim
startArea     the area id the Master begins in
credits       the licence/credit line, verbatim
```

### `adventureArea`
```
id            area.<adventure>.<slug>
area          the printed area number (1-8)
name          the printed title, verbatim
description   the printed description, verbatim
hint          the grey Hint paragraph, verbatim (gated — see below)
line          an authored line for the beat screen (ours; label invention)
exits         area ids reachable from here (I-42)
gate          null, or { key, text } — the lock on entering this area
treasures     treasure ids found here by exploration, not loot (I-38)
```

### `adventureEncounter`
```
id            encounter.<adventure>.<area-slug>.<n>
area          the area number this row belongs to
faces         the 1d6 faces this row covers; [] for a fixed encounter (I-34)
foes          foe ids met (two ids = the Attendants room's "Both", R35)
count         'one' | 'band' | 'oracle' | 'none'
empty         true for the Chieftain quarter's 5-6 (I-36)
```

### `adventureLoot`
```
id            loot.<foe-slug>.<n>
foe           the foe id
faces         the 1d6 faces this row covers; [] for a single named drop
item          the item text, verbatim ("junk", "simple weapon", "Spear")
treasure      a treasure id where the drop is one of the five, else null
key           a key id where the drop is a key, else null
hint          true for the Devil servant's silent 6 (I-08)
once          true where the drop is unique (I-33c: the sword drops once)
```

### `adventureTreasure`
```
id            treasure.<adventure>.<slug>
name          the printed name, verbatim
effect        the printed effect, verbatim
source        'area' | 'loot'
sourceRef     the area id or foe id it comes from
knownFrom     ids that reveal the effect (I-38b, I-41, I-60); [] = on acquiring
```

### `adventureFlag`
```
id            flag.<adventure>.<slug>
flag          the flag name the engine reads
initial       its value at the start
text          what it means, one line
```

### `adventureAct`
```
id            act.<adventure>.<n>
act           1..n; the last act is the ending
name          the act's name
condition     'treasures' | 'foe' | 'enter'  — what advances into it
threshold     the count or the id the condition tests
line          the authored line the marker reads (ours)
ending        true on the last row: this is the ending screen
```

## Engine — `packages/engine/src/adventure/`

Pure, dice injected, no adventure-specific branching. Files, each with a
colocated test and every export registered in `behaviours.ts`:

| File | Exports |
|---|---|
| `state.ts` | `AdventureState`, `beginAdventure`, immutable updates |
| `event.ts` | `rollEvent` — the 1d6 table, and `EventKind` |
| `graph.ts` | `exitsFrom`, `canEnter` (locks and keys), `enterArea` |
| `encounter.ts` | `encounterIn` — the area's table, defeated named foes removed (I-33b, I-33c), Ogres absent by night (I-45), "Empty" degrading to Safe exploration (I-36) |
| `hints.ts` | `revealHint` — Event 6, or "information" (I-06b, I-60) |
| `loot.ts` | `lootFrom` — the foe's rows, keys and treasures picked up |
| `acts.ts` | `actFor`, `ending` — act markers and the ending screen |
| `run.ts` | `step` — one Master turn: enter, event, resolve, advance |

`step` is the function the scripted playthrough drives. It takes state, a
`DiceSource` and a player choice; it returns the next state and a list of
what happened. It never rolls a fight: combat is Phase 3's, and `step`
returns the encounter for the caller to resolve.

## Tests

- **`packages/content`**: the schema leg covers the new files
  automatically; add reference tests (every `foe`, `area`, `treasure` and
  `key` id in the cave resolves), a count row per new file in
  `counts.ts` / `EXPECTED_RECORD_COUNTS`, and one test binding the
  retired prototype beats to the new areas by name.
- **`packages/engine/src/adventure/adventure.test.ts`**: unit tests per
  file, plus **`playthrough.test.ts`** — a scripted Master on
  `fromSequence` fixed dice who walks mountain -> entrance -> hall ->
  attendants (key) -> chieftain -> women -> storage -> kitchen, takes all
  five treasures, and lands on the ending screen. That test is the
  phase's done-condition.

## Conventions

- Every new engine export carries `{label, cite}`; readings cite their
  `I-nn`, inventions cite this brief.
- Verbatim text is verbatim: no normalisation outside ids.
- No React, no I/O, no dice of the engine's own.
- The SVG is original — drawn from the adjacency table in `map.md`, never
  traced from the source image.
