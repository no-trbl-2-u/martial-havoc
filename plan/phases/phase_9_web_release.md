## Outcome

The Cloudflare URL stops being a place the build happens to land and
becomes **the release**: a page that names itself and its authors before
it loads, installs to a phone's home screen, opens with no network, and
carries a checklist in the repository that says what was checked.

**Done when** (the build-plan row): the Cloudflare URL serves the
milestone build; the release checklist is in the repository and ticked.

The row also names "the operator installs the web app to a phone". That
is the operator's action, not the agent's. This phase's obligation is to
make it **possible and correct** — a manifest, an icon, a display mode,
a theme colour — and to say in the checklist that the install itself is
the one item only the operator can tick.

## The document shell, in detail

`expo export --platform web` uses `apps/app/public/index.html` as its
template when one exists and injects the bundle's `<script>` before
`</body>`; everything else under `public/` is copied to the export root
verbatim. Both were verified against this build before this brief was
written, not assumed.

The template must carry the `expo-reset` styles the default template
supplies — `html, body { height: 100% }`, `body { overflow: hidden }`,
`#root { display: flex; height: 100%; flex: 1 }`. Dropping them breaks
the frame's full-height layout, silently and only on the export.

**Offline** is a service worker with two rules and no third:

- `_expo/static/**` is **cache-first**. Those filenames are content
  hashed, so a cached one can never be stale.
- Everything else, `index.html` included, is **network-first with a
  cached fallback**. A reload with no network serves the last good
  shell; a reload with network always gets the new one.

That is the whole policy. It cannot serve a stale app, which is the
failure mode a cache-first shell has, and it is why the two rules are
split by path rather than by a version string the build would have to
thread through.

## Metadata

| Tag | Value | Why |
|---|---|---|
| `<title>` | Martial Havoc | `app.title`. |
| `description` | `app.tagline` | The one sentence the Seed wrote. |
| `theme-color` | `#16110C` (the ink) | The woodblock tokens; the phone's chrome matches the frame. |
| `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style` | yes, black-translucent | iOS installs without them read as a browser tab. |
| `viewport` | adds `viewport-fit=cover` | The frame is edge to edge on a notched phone. |
| `manifest` | `/manifest.webmanifest` | The install. |

The manifest: `display: standalone`, `orientation: portrait` (matching
`app.json`), `start_url: /`, background and theme from the tokens, and
one `icon.svg` at `any maskable`. **An SVG icon, not a PNG** — the
licence line says text and SVG only, and an authored mark is ours.

There is no JSON-LD and no OpenGraph image. This is an offline solo
game with no server and no social surface; a share card would be
scaffolding for a thing the Seed refuses.

## Empty / loading / error states

The About screen has none: every number it shows is a bundled constant,
so it cannot be empty, pending or failed. The service worker's failure
state is the one that exists, and it is the cached shell.

## Decisions made upfront — DO NOT ASK

1. **The icon is authored, not extracted.** No credited art ships
   (`app.licence`). The mark is a woodblock seal in the ink and
   vermilion already in `theme/tokens.ts`, drawn in this repository.
2. **Service worker, not a cache manifest or a framework.** No Workbox,
   no dependency. Thirty lines of `fetch` handler, two rules, tested by
   Playwright going offline and reloading.
3. **No stale-shell risk taken for a faster load.** Network-first on the
   document is a few hundred milliseconds worse on a warm cache and
   cannot ship yesterday's app. For a game a player returns to over
   weeks, that trade is not close.
4. **`registerServiceWorker` is guarded and never fatal.** A browser
   without one, a refused registration, an insecure origin: all are a
   normal app with no offline reload, never an error the player sees.
5. **Counts are printed by a script and shown on a screen.** The row
   asks for "content counts printed"; `npm run counts` is the printed
   form for the checklist and CI, the About screen is the readable form
   for a player. Both read `contentCounts`, so they cannot disagree.
6. **The checklist lives at `plan/RELEASE.md`** beside the other plan
   state, not at the repo root. It is loop state, and `/march` reads
   `plan/`.
7. **The install is the operator's tick.** Every other line of the
   checklist is a command an agent runs and a result it records. The
   install cannot be, and the checklist says so rather than pretending.
8. **No custom domain.** `plan/bearings.md`: "A custom domain is the
   operator's call." Unchanged here.
