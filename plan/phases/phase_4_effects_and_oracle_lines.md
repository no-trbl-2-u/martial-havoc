## Outcome

the count is readable from the build (`contentCounts`).

The 149: **72** Technique and Ritual effect records, **66** Oracle cells
and **11** Unexpected Events, one authored line each.

## The central design question this phase answers

Reading **A23** is the one row of the estate's inventory with *no*
defensible inference: "All 72 Technique/Ritual effects are prose without
numbers - the central design question." It offers a classification "the
operator could adopt", and this phase adopts it:

| Class | What it means mechanically | A23's examples |
|---|---|---|
| `mechanical` | A number the engine applies | Body and Mind balance, Punishing the sky, Vital Breath, Chain Fists, Butterfly Palms, Light Body, Lord of the Bow, Iron Shirt |
| `combat-narrative` | Resolved as an Opening or an escape per R28 | knock-downs, intimidation, immobility, indestructibility |
| `exploration` | Gating, like R69's expedition items | climb, swim, run on water, find the way, weather |
| `oracle-like` | Resolved by an Oracle or Sparks roll | Book of Changes, Acting without acting, Wheel of Existence, The Way of Tao |
| `summoning` | A companion, or an Unexpected-Event-like table | Protective Demon, Older Brother, Eight Celestial Drunkards |

Every effect record carries `label: invention` with `cite` naming A23 and
the folio its Technique is printed on. The **effect text stays verbatim**
in `world/techniques.json` and `world/rituals.json`; nothing in this phase
edits a transcription.

## Shape: authored records reference transcribed ones, never replace them

Standing rule 9.1 says transcribe, don't paraphrase. So the authored lines
ship as **new files whose records point at the existing ids**, leaving
every transcribed table untouched:

| New data file | Records | References | Record kind |
|---|---|---|---|
| `world/effects.json` | 72 | `technique.*` and `ritual.*` | `effect` |
| `world/oracle-lines.json` | 66 | `oracle.*` | `authoredLine` |
| `rules/unexpected-event-lines.json` | 11 | `unexpected-event.*` | `authoredLine` |

### `effect` record

```
id          effect.<technique-or-ritual-id>
ref         the transcribed record's id (must resolve)
class       mechanical | combat-narrative | exploration | oracle-like | summoning
cost        1-4, copied from the transcribed record (R16, R18)
timing      immediate | combat-winner-option | scene | preparation
operation   the engine call the class implies, or null for narrative-only
line        the authored line - what the table reads when it fires
cite        "MH p.<folio>; A23"
```

`timing` follows the book, not taste: a Technique is `immediate` outside
combat and `combat-winner-option` inside it (R14, R25, I-23); a Ritual is
`preparation` - "not usable during combat rounds; usable in any scene,
costing a scene or a Rest event" (I-24). Wudang is R13's exception and is
flagged on the record, not hardcoded in the engine.

### `authoredLine` record

```
id     line.<referenced-id>
ref    the transcribed record's id (must resolve)
line   the authored line
cite   "MH p.<folio>"
```

## Schema work

`packages/content/schema/content.schema.json` gains two record kinds
(`effect`, `authoredLine`) under `$defs/records`, both admitted by the
existing `list` file kind. Every object stays closed
(`additionalProperties: false`). No new **file** kind: these are lists.

## Tests (`packages/content/src/*.test.ts`)

1. Schema validation of the three new files (the existing validator leg
   picks them up automatically).
2. **Referential integrity:** every `ref` resolves to a record that exists,
   and every Technique, Ritual, Oracle cell and Unexpected Event has
   exactly one authored record. This is what makes "149" checkable rather
   than asserted.
3. **Counts:** `contentCounts` reports 72 / 66 / 11 and their sum, and a
   test pins 149.
4. Every `class` is one of the five; every `cost` matches the transcribed
   record it references; every `timing` is legal for its kind (a Ritual is
   never `combat-winner-option`, per I-24 and I-23).
5. No authored line is empty, and none duplicates the verbatim effect text
   - a line that just restates the transcription is not an authored line.

## Conventions

- Authored lines are **ours**: `label: invention` at the file level, cited
  to A23 (effects) or the folio (Oracle and Unexpected Event lines).
- Second person, present tense, one sentence, no emoji, no em dash.
- A line names what the fiction does, never a number the record already
  carries.
- The operator may reserve any record: mark it `[needs-user-call]` in the
  brief's own carry-over list rather than authoring it. The agent drafts
  all 149 by default (build-plan row).

## Done when

3. `npm run verify` is green end to end.
