## Outcome

`packages/engine/src/campaign/` — the campaign record as a pure,
immutable value with a versioned JSON export and an import that migrates
rather than refuses; the app persists **that** instead of dumping its
whole screen state to storage.

**Done when** (the build-plan row): a record survives export, import and
one migration in tests; the override count increments on a non-dice
manual entry.

## The distinction this phase draws

Today `apps/app/src/state/types.ts` has one `RecordState` holding both
the campaign (sheet, deeds, passages, overrides, held treasures) and the
session (`screen`, `manualOpen`, `draft`, `openId`, `filter`), and
`persist.ts` writes the whole thing to `localStorage`. Two things are
wrong with that: a UI field change silently invalidates every save, and
the durable half has no version story beyond `version: 1`.

So:

| | Lives in | Persisted | Owned by |
|---|---|---|---|
| **Campaign record** | `packages/engine/src/campaign/` | yes, versioned | the engine, pure |
| **Session state** | `apps/app/src/state/` | no | the app |

`RecordState` keeps both at runtime; only the campaign half is written
out, and only the campaign half migrates.

## The record

```
CampaignRecord
  version        the record format version (an integer, bumped by a migration)
  readings       the reading ids in force when it was written (["I-05", ...])
  master         the Master: sheet numbers, initials, gold, dishonor,
                 proficiencies, techniques, and the overspend mark
  dead           the world dies with the Master (bearings); set, never unset
  adventures     per-adventure state, keyed by adventure id:
                 area, visited, flags, defeated, keys, items, treasures,
                 hints, effects, rescued, dishonor  (Phase 5's AdventureState)
  deeds          the deeds ledger, in the order they happened
  passages       what the player wrote, in order
  overrides      how many rolls were typed instead of rolled
```

`master.overspent` is the creation overspend mark: `spec.md` refuses to
block an overspent pool, so the record carries the flag instead
(`creationClean` / `raisedFlags` already produce it).

## Continue or fresh start

`bearings.md`: "Continue or fresh start at each scene; the world dies
with the Master." Two functions, both total:

- `canContinue(record)` — false once `dead` is set.
- `freshStart(record)` — a new record that keeps nothing but the format
  version and the readings. The dead Master's world does not survive.

## Export, import, migration

```
exportCampaign(record) -> CampaignFile      the versioned envelope
importCampaign(unknown) -> ImportResult     total; never throws
```

The envelope names the format so a file from anywhere is recognisable:

```
{ format: "martial-havoc/campaign", version: <n>, exported: <iso>, record: {...} }
```

`importCampaign` returns a **result, not an exception** (`spec.md`,
Refusals: a refusal is data). Three outcomes: `ok` with the record,
`ok` with the record and the migrations that were applied, or `rejected`
with a reason a screen can render.

**Migrations are keyed on reading ids.** Each is
`{ from, to, reading, why, migrate }`: `from`/`to` are record versions,
`reading` is the `I-nn` whose position changed and forced the bump, `why`
is one line. The chain runs in order from the file's version to the
current one; a version above the current one is rejected (a save from a
future build), a gap in the chain is rejected. `readings` on the record
is rewritten to the build's own list as the last step, so a re-export is
current.

Version 1 is the shape the prototype wrote. The **first real migration**
this phase ships is 1 → 2: v1 had no `adventures` map and no `readings`,
because the adventure format did not exist until Phase 5. It is keyed on
`I-33b` (re-entry and respawn — the reading that made per-adventure state
necessary at all).

## Tests

- `packages/engine/src/campaign/campaign.test.ts` — the record's own
  updates, `canContinue`, `freshStart`, the world dying with the Master.

- `apps/app/src/state/reduce.test.ts` — the override count increments on
  a non-dice manual entry and not on a rolled one.

## Conventions

- Every new engine export carries `{label, cite}` with a rules-panel
  note; the record's shape is `invention` citing this brief, the
  overspend mark and the dead-world rule cite what they come from.
- Pure: no `Date.now()` inside a record function. The export timestamp is
  passed in.
- No React, no I/O in the engine. `persist.ts` keeps the storage guards
  it already has.

## Out of scope

- A save/load screen, an export button, a file picker. Phase 8.
- Multiple campaigns at once. One record per campaign; a picker is UI.
- Cloud sync of any kind (`spec.md`, Refusals).
